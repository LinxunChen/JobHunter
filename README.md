# JobHunter · 国央企与金融机构求职监控台

**51 个重点机构目录 · 40 个招聘来源适配 · 1 个公告发现渠道**

把逐个刷招聘官网，变成一份可跟踪的求职清单。从岗位发现、报名条件核验和个人经历匹配，到截止提醒、关注与投递记录，在本机完成管理。

内置机构目录涵盖中国银行、建设银行、工商银行、国家电网、运营商研究院，以及证券、基金、保险等重点机构。当前招聘适配关联目录中的 **41 个目标机构**；51 是目录规模，40 是招聘来源适配数量，均不代表每家机构全部岗位都已完整获取。各入口的实际覆盖和缺口可在来源页面查看。

适合希望持续关注国央企与金融机构、保留判断依据并自行投递的个人用户。默认是北京的技术岗位社会招聘，修改设置即可调整目标城市和岗位关键词。**本版校招仅提供配置预留，现有来源尚未接通校招；非技术方向未完成真实推荐质量验收。**

## 能做什么

- **发现与保存**：读取已接入的公开招聘列表和详情，保留原文、附件、来源版本与读取缺口。支持手动补录岗位和公告。
- **资格核验**：将明确的学历、专业、年龄、证书和经历要求与个人事实分别核验；没有证据的条件保持待核验。
- **岗位匹配**：通过 Codex 分别解释专业技术、业务和职责层级的对应关系，区分直接经历、可迁移能力和差距。不给录用概率。
- **申请管理**：关注、排除、已投递、简历版本、面试与申请结束分别保存；打开投递链接不会自动标记已投递。
- **持续跟踪**：按北京时间安排当前周期检查、跟踪截止日期和岗位变化，支持中断恢复、处理队列和每日模型预算。
- **提醒与恢复**：生成求职日报预览，可选 PushPlus；提供完整备份、核验和隔离恢复。

来源成功获取、岗位当前开放、个人资格符合和匹配程度是四种独立事实。公开列表不是完整覆盖的保证，岗位推荐也不保证招聘审核或录用。

## 快速开始

### 1. 启动工作台

需要 Node.js **22.16.0 或更新版本**，包含 `node:sqlite`。项目使用原生 Node 模块，当前没有 npm 第三方运行依赖。

```sh
node --version
npm ci
npm start
```

打开 [本机工作台](http://127.0.0.1:3210/sources)。服务只监听 `127.0.0.1`，首次启动会在 `.data/` 创建本地数据库，不自动开始来源检查、安装系统服务或启用通知。

仅浏览、补录和管理投递可以先不配置模型。需要自动抽取公告或匹配岗位时，再配置可用的 Codex CLI 与已有登录状态。程序优先使用 `JOBHUNTER_CODEX_COMMAND` 指定的绝对路径，其次寻找桌面应用附带入口或 PATH 中的 `codex`。不会自动登录、安装 CLI 或修改全局配置。

```sh
JOBHUNTER_CODEX_COMMAND="$(command -v codex)" npm start
```

模型当前固定为代码中的 `gpt-6.1-sol`；账户与 CLI 需要支持它。任务通过受控 CLI 运行，禁用工具与额外上下文，实际模型调用可能消耗账户额度。

### 2. 填四项设置

在“来源与设置”底部进入“目标岗位设置”或“个人资料”，也可直接打开 [个人与目标设置](http://127.0.0.1:3210/settings)。

| 主要输入 | 怎么填 |
| --- | --- |
| 目标城市 | 北京、上海等，一个或多个；留空不限，不用单位总部推断工作地点 |
| 目标岗位 | 直接填写算法、软件研发、人力资源等关键词；任一命中即可，留空不限，无需切换模式 |
| 招聘类型 | 社招、校招、不限；校招来源未接通时明确跳过，“不限”只检查已支持类型 |
| 个人资料 | 粘贴已确认的经历、技能、项目与教育信息，无需重复填资格长表 |

点击一次“保存设置”即可。排除关键词、薪资、岗位层级、行业及用工关系等写入可选偏好；未披露的信息不会因此自动淘汰。目标机构在来源页面管理，知识库连接收进高级设置。

保存目标不启动岗位采集或批量重算。资料有实质变化时会异步调用已配置的 Codex 提取资格事实，页面显示进度；同一版本成功分析后复用结果。自动分析使用全项目每日模型预算，额度或连接不足时保留资料等待后续处理。缺失、冲突或无法逐字核对的信息保持待核验，已有手动确认事实不会被静默覆盖，可展开“查看与纠正已识别信息”。

职业资料更新创建版本；已有岗位、原文和真实投递记录保留，受影响的解释标记待更新。关键词只决定处理范围，不代替完整JD和个人经历匹配。

资料、资格事实与本机配置不属于公开源码。**本地保存不等于离线分析**：分析与匹配会将资料正文传给配置的 Codex 模型，请勿填写无关隐私和联系方式。

### 3. 选择来源检查

在目标机构表格中保留需要的机构，暂停或移出其他机构，然后点击“立即检查”。不确定时先只检查一家。

- 基础启动接入中国银行、建设银行、工商银行、中国移动研究院、易方达相关招聘入口，以及北京国资委发现栏目；各来源具体覆盖以页面详情为准。
- 更多已有适配器见 [扩展来源目录](src/expanded-source-catalog.mjs)。启用扩展来源可在启动时设置 `JOBHUNTER_EXPANDED_SOURCES=1`；接入会保存到当前数据库，之后可在页面暂停。
- 北京国资委属于固定地域的公告发现渠道。修改目标城市不会把它变成其他城市的国资委；可暂停该渠道，使用支持相应地点的已有来源或手动补录。
- 新增机构和链接只保存目标与线索，**不会自动生成新采集器**。新的站点仍需来源适配开发。
- 登录、验证码、访问验证、缺失职责或无法取得的附件会如实显示缺口；不会绕过访问限制，也不会以抓取失败推断招聘结束。

岗位加工与匹配受本地预算和每轮处理上限控制，较多线索可能分多轮处理。当前自动公告加工、匹配与个人资料分析共用每日 50 次模型尝试预算，失败也计数；明确的手动加工另计。完整取得原文不表示所有岗位都已完成匹配。

## 日常使用

| 页面 | 用途 |
| --- | --- |
| 岗位库 | 查看岗位、推荐解释、资格缺口、官方报名时间与申请入口 |
| 我的关注 | 查看主动关注的岗位，持续跟踪变化 |
| 我的投递 | 记录真实申请、所用简历及后续事件 |
| 来源与设置 | 检查机构、查看当前问题、管理来源和个人配置 |
| 消息预览与记录 | 查看日报内容与发送台账 |
| 备份与恢复 | 创建完整包、核验、恢复到隔离目录 |

没有后台服务时，Web 进程本身不会代替每日调度器。手动运行一个当前检查周期：

```sh
node src/run-scheduled.mjs
```

该命令可能访问启用的来源、调用模型，以及在通知已明确配置启用时发送业务提醒。采用北京时间每日 09:00 的计划与离线补查规则，同日不强制重复已完成周期；不是无限循环的守护进程。首次调试请使用隔离数据库，按需停用通知。

macOS 的可审阅常驻计划和通知配置见 [运行与运维说明](ops/README.md)。常驻安装、睡眠唤醒和系统配置不由 `npm start` 自动处理。

## 配置与本地数据

| 变量 | 默认值／含义 |
| --- | --- |
| `JOBHUNTER_DB` | `.data/job-hunter.sqlite`；Web、后台与来源子进程应使用同一路径 |
| `JOBHUNTER_PORT` | `3210`，只监听本机 |
| `JOBHUNTER_CODEX_COMMAND` | Codex CLI 的绝对路径；未设置时尝试现有桌面入口与 PATH |
| `JOBHUNTER_ATTACHMENT_PYTHON` | 附件读取的隔离 Python 绝对路径 |
| `JOBHUNTER_EXPANDED_SOURCES` | 首次注册扩展来源时设为 `1`；后续暂停用页面开关 |
| `JOBHUNTER_VERIFICATION` | 设为 `1` 进入恢复核对模式，停用外部接入与业务写入 |

目标配置保存在所用数据库中；多个数据库互不共享个人设置。可选的数据库同目录 `local-settings.json` 用于本机初始配置，Web 保存的值优先。不加载 `.env` 文件；请由 shell 或服务环境传入变量。

```json
{
  "targetCities": ["上海", "杭州"],
  "roleKeywords": ["数据分析", "风险管理"],
  "recruitmentType": "social",
  "preferences": "关注可独立负责专业领域的岗位",
  "excludedKeywords": ["销售"],
  "careerDocumentId": "",
  "careerSettingsPath": ""
}
```

默认采用手动职业资料。若使用现有本地知识库，可在高级设置填写已授权的职业文档 ID 和 MCP 配置文件绝对路径。读取仅使用启用鉴权、监听 `127.0.0.1` 的现有连接，完整分页后才采用；不扫描其他笔记，不安装或修复 MCP。无需接入知识库也能通过手动资料完成匹配。

`.data/` 中可能包含履历、资格事实、申请、通知、原文附件和备份；`.runtime/` 包含运行过程文件。都应按私人数据管理。备份包含数据库与其中的个人配置和资料；外置凭据和本地 JSON 需另外安全保存。本机备份不能防止整盘损坏。

## 附件与平台依赖

文本与 HTML 可直接读取。PDF、Word 和 Excel 附件需要隔离 Python；图片 OCR 当前依赖 macOS Vision 与 Swift，因此完整图片能力尚不支持 Linux／Windows。

可在项目中创建虚拟环境，按需安装附件库，不使用全局 pip：

```sh
python3 -m venv .runtime/attachment-venv
.runtime/attachment-venv/bin/python -m pip install pypdf python-docx openpyxl
.runtime/attachment-venv/bin/python -m pip install --require-hashes -r scripts/attachment-requirements.txt
JOBHUNTER_ATTACHMENT_PYTHON="$PWD/.runtime/attachment-venv/bin/python" npm start
```

部分来源使用系统 `curl`；图片读取需要 macOS 工具链。没有相应能力时保留原附件及读取失败原因，不捏造已读内容。上述三个通用附件库尚未提供统一版本锁定，这是跨机器复现的已知限制。

## 开发与验证

```sh
npm test
```

测试以共用应用入口、临时 SQLite、HTTP 和受控来源／模型夹具验证行为。完整套件还需要附件 Python、macOS 图片处理和 `plutil`；缺少这些环境时不能把相关场景称作已通过。

测试中的招聘样本和模型输出用于确定性回放，不代表当前官网可用、岗位仍开放或真实模型已执行。真实来源与真实模型应分开验证，PushPlus 接口接受也不等于最终送达。

代码按应用入口与领域模块组织：

```text
src/application.mjs          Web 与后台共用应用边界
src/server.mjs               本机 HTTP 服务
src/local-settings.mjs       配置持久化与调用上下文
src/job-relevance.mjs        城市、招聘类型与岗位关键词规则
src/profile-analysis.mjs     异步资料提取、证据与版本恢复
src/*-source.mjs             来源适配与原文采集
src/announcements.mjs        公告、附件与逐岗派生
src/eligibility.mjs          独立资格核验
src/matching.mjs             职业资料与匹配版本
src/scheduled-run.mjs        周期、恢复与执行步骤

```

## 安全公开源码

日常开发仓库可能积累了私人历史、实施笔记、截图和本机路径。**不要直接将自己的工作仓库或旧 Git 历史发布。** `.gitignore` 不会清除已经跟踪的文件，更不会删除历史提交。

生成一份不携带 Git 历史的源码目录：

```sh
npm run export:public
```

默认输出 `.runtime/public-release/`，已存在则拒绝覆盖；也可指定一个新的导出目录：

```sh
node scripts/public-release.mjs --output .runtime/public-release-v2
```

导出只包含明确列入的源码、测试、公共夹具、脚本与使用文档，排除 `.git/`、`.data/`、`.runtime/`、`.scratch/`、代理说明和私人实施记录。导出前扫描当前用户目录标记、本地职业来源标记、私人会话链接与常见密钥格式。可将自己的姓名、邮箱等追加到本地 `.data/privacy-markers.json` 字符串数组，命中时拒绝导出，只报告文件名。

自动扫描无法证明识别了所有个人信息。发布前还应人工审阅导出文件，并在这个干净目录建立全新仓库。导出命令不会执行 `git init`、提交、推送或修改原仓库历史。仅给旧仓库加一条忽略规则，不能把它变成安全的公开发布物。

## 当前边界与后续方向

- 本工具面向单人、本机使用，没有多用户认证、权限隔离或互联网部署加固；不要直接暴露公网。
- 自定义城市和关键词复用现有执行链路，不会扩大官网自身覆盖。默认技术目标保留已有规则回归；其他方向的配置可保存并传递，但本轮没有进行真实推荐质量验收。
- 来源适配紧随官网结构，网页改版可能需要修复；内置接入记录只是历史观察，不是持续可用承诺。
- 模型与 CLI 当前固定，跨 CLI 版本／账户兼容仍需实际验证；Linux／Windows 的完整适配、统一依赖锁定、CI 与安装诊断还需补齐。
- 本轮优先抽离配置和私人资料边界；更大范围的来源插件协议、HTTP 路由拆分和多用户架构适合后续独立实施。
- 当前未声明开源许可证。对外分发前需要项目所有者选择许可证，并另行审阅公共网页样本的再分发条件。

JobHunter 提供可追溯的求职辅助信息；最终报名条件、职位状态和申请流程以招聘方最新原文为准。
