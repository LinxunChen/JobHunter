# 本地运行与运维

## 启动与调度

```sh
npm start
node src/run-scheduled.mjs
```

Web 与后台都使用 `createProductionApplication`，读取同一数据库目录下的本地配置。Web 默认 `127.0.0.1:3210`；单次后台依据北京时间每日 09:00 的计划决定是否检查或补查，不代表已经安装常驻服务。

macOS 可先生成计划供人工审阅：

```sh
node ops/runtime-plan.mjs --plan
node ops/runtime-plan.mjs --prepare
```

工具根据当前项目目录、Node 和现有运行时生成路径；仅在项目 `.runtime/service-install-plan/` 准备文件，不运行 `launchctl`。已有目标或不安全路径会拒绝覆盖。安装前审阅 `plan.json` 中的完整命令、XML、端口、日志和运行时路径；登录加载、睡眠和重启行为需要分别验证，不保证准点唤醒。

## 可选 PushPlus

默认不发送消息。配置位于所用数据库目录的 `credentials/pushplus.json`，仅接受以下字段：

```json
{
  "enabled": false,
  "queryEnabled": false,
  "token": "",
  "accessKey": ""
}
```

自行填入自己的凭据。凭据目录须为当前用户拥有的普通目录、权限 `700`，文件须为当前用户拥有的普通单链接文件、权限 `600`；不接受符号链接。勿把 token 放入命令参数、日志、截图或 Git。

`enabled=true` 表示启用实际发送；需要有效 token。`queryEnabled=true` 还需要 accessKey，用于已发送结果查询。修改后需重启 Web，单次调度器下次启动时读取新配置。仅在明确希望发送时启用，先审阅消息预览。关闭配置不撤销已发请求。

发送台账区分接口接受、失败、未知及服务结果。项目每日发送尝试上限不代表服务账户还有额度，也不证明接收者已阅读。

## 备份与恢复

通过 Web 创建完整备份；周日、手动、升级前备份合计保留最近 3 份，新包完整核验后才淘汰自管超额旧包并清理已确认归属的失败暂存。失败不挤掉成功包，保留失败诊断；未知目录不自动删。升级前仍须先建立完整快照，但没有额外长期保留池。3 份按快照数量计算，不保证覆盖 3 周；多个升级可能缩短可回退时间。数据库中职业资料、资格、个人配置和申请也属于私人备份内容，不可随源码分发。

恢复仅写新的隔离目录，默认开启恢复核对标记，停用来源、模型、通知和业务写入。使用新路径与独立端口检查：

```sh
JOBHUNTER_DB="/absolute/path/restored/job-hunter.sqlite" JOBHUNTER_PORT=3211 JOBHUNTER_VERIFICATION=1 npm start
```

外置凭据及 `local-settings.json` 不随备份复制，需另行保管。确认完整回读之前不要替换原数据库；SQLite 使用 WAL，不能在运行中仅复制主文件当作完整备份。

## 更新代码

先创建升级前备份，保留 `.data/`、`.runtime/` 和自己的本地配置，再更新代码并重启 Web。后台运行时应避免交叉执行迁移或人工修复。所有故障以原文、检查回执和可复现证据为准；不要把服务在线等同业务检查完成。

## 临时验收文件的收口

完整备份按上述3份池维护。已结束任务的回放/压力测试数据库和浏览器缓存不作为长期额外备份积累；确认无进程使用并核对数据覆盖后，可按已授权清单清理。副本中独有的岗位原文、附件、个人/投递历史和必要验收数据应先精确去重保存并核验SHA，保留来源映射；包含未覆盖原始材料的副本继续保留，不能只因文件大就删除。

保留规格、脚本、测试结论、失败日志、关键截图和回执。不要把整个 `.runtime/` 当作缓存，也不要删除在用SQLite的WAL/SHM、活动日志、下载原件、凭据或运行时环境。清理后核对正式数据、3份完整包及Web/调度；临时副本已删除时，记录其新追溯位置，不宣称仍可按旧路径完整恢复。
